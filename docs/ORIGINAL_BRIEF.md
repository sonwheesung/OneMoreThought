# 행동 개입 앱 기획서

## 1. 서비스 개요

### 한 줄 정의

**내가 피하고 싶은 앱을 열 때는 한 번 더 생각하게 하고, 내가 열어야 할 앱을 잊었을 때는 다시 알려주는 자기관리 앱.**

### 핵심 철학

> 막지 않는다.  
> 대신 필요한 순간에 한 번 개입한다.

사용자의 앱 사용을 강제로 차단하지 않는다.

대신 사용자가 미리 설정한 규칙에 따라 두 가지 방식으로 개입한다.

### ① 열려고 할 때

YouTube를 실행하려고 함.

> `돈 벌어야지.`

**[취소] [그래도 열기]**

### ② 열지 않았을 때

오늘 일기 앱을 한 번도 실행하지 않음.

23:00이 됨.

> `오늘 일기 잊은 거 아니야?`

**[나중에] [일기 열기]**

---

# 2. 해결하려는 문제

사람들은 해야 할 일과 하지 말아야 할 일을 알고 있어도 순간적으로 잊는다.

예를 들어:

- 업무시간인데 습관적으로 YouTube를 누른다.
- 다이어트 중인데 무심코 배달 앱을 연다.
- 자기 전에 SNS를 열어버린다.
- 매일 일기를 쓰려고 했는데 일기 앱 자체를 여는 것을 잊는다.
- 매일 영어 공부를 하려고 했는데 영어 앱을 열지 않았다.

기존 앱 차단 서비스는 주로 첫 번째 문제를 해결한다.

하지만 이 앱은 두 방향을 모두 다룬다.

> **하지 않으려던 행동을 하려고 할 때**

그리고

> **하려던 행동을 하지 않았을 때**

# 3. 핵심 기능 구조

제품은 크게 두 종류의 규칙으로 구성한다.

## A. 실행 전 확인

**열려고 하는 앱에 개입**

```text id="h99gh4"
대상 앱 실행
    ↓
현재 규칙 확인
    ↓
조건에 해당
    ↓
내가 설정한 메시지
    ↓
[취소] [열기]
```

## B. 실행 확인

**열어야 하는 앱을 안 열었을 때 개입**

```text id="3x6onh"
하루 시작
   ↓
대상 앱 실행 여부 확인
   ↓
설정한 확인 시간 도달
   ↓
오늘 실행했음 → 아무것도 하지 않음
오늘 실행 안 함 → 알림
```

두 기능 모두 하나의 공통 개념을 가진다.

> **앱 사용 행동에 조건을 걸고 필요한 순간에만 개입한다.**

# 7. 기능 B: 실행 확인

두 번째 핵심 기능이다.

사용자가 **해야 할 행동과 연결된 앱을 오늘 실행했는지** 확인한다.

중요한 점은 앱 내부 행동까지 확인하지 않는다는 것이다.

예를 들어 일기 앱이라면:

- 일기를 작성했는가? → 확인하지 않음
- 몇 글자를 작성했는가? → 확인하지 않음
- 앱을 오늘 실행했는가? → 확인

즉 매우 단순한 기준을 사용한다.

> **오늘 이 앱을 열었는가?**

## CASE A

18:32

사용자가 조각 앱을 실행했다.

앱은 오늘 실행 여부를 기록한다.

```text id="n4vzxb"
오늘 실행

조각 ✓
```

23:00이 되어도 아무것도 하지 않는다.

---

## CASE B

23:00까지 조각 앱을 한 번도 실행하지 않았다.

```text id="4lyh45"
┌─────────────────────────┐
│ 📔 조각                 │
│                         │
│ 오늘 일기 잊은 거 아니야?│
│                         │
│ 나중에        일기 열기  │
└─────────────────────────┘
```

**일기 열기**

→ 조각 앱 실행

**나중에**

→ 알림 종료

# 10. 두 기능의 차이

| | 실행 전 확인 | 실행 확인 |
|---|---|---|
| 목적 | 충동 억제 | 할 일 상기 |
| 조건 | 앱을 실행하려 함 | 앱을 실행하지 않음 |
| 시점 | 실행 순간 | 지정 시간 |
| 예 | YouTube | 일기 |
| 메시지 | 돈 벌어야지. | 오늘 일기 잊었어? |
| 행동 | 취소 / 열기 | 나중에 / 앱 열기 |

이 두 기능을 명확하게 구분한다.

# 15. 하루의 기준

실행 여부는 날짜 단위로 관리한다.

예:

```text id="t5b67n"
2026-10-06

조각       실행함
리디        실행 안 함
운동 앱     실행함
```

날짜가 변경되면 새로운 하루로 판단한다.

사용자가 앱을 한 번이라도 실행했다면 그날의 조건은 충족된다.

앱을 얼마나 오래 사용했는지는 MVP에서 판단하지 않는다.

---

# 16. 여러 번 알림

MVP에서는 **과도하게 반복하지 않는다.**

실행 확인 알림이 한 번 발생한 뒤 사용자가 `나중에`를 선택했다고 해서 5분마다 계속 알림을 보내지 않는다.

기본:

> 하루 최대 1회

향후 사용자가 원하는 경우:

> 30분 후 다시 알림

같은 기능을 추가할 수 있다.

# 17. 실행 전 확인 예외 처리

사용자가 `열기`를 선택한 직후 같은 앱을 다시 감지하여 Confirm이 무한 반복되면 안 된다.

따라서 일시적인 통과 상태가 필요하다.

예:

```text id="40knbt"
YouTube 실행
 ↓
Confirm
 ↓
열기
 ↓
YouTube 허용
 ↓
일정 시간 동안 재감지 무시
```

사용자가 직접 YouTube를 종료하고 나중에 다시 실행하면 새로운 Confirm을 표시한다.

# 21. 권한 온보딩

이 앱은 일반적인 할 일 앱보다 Android 시스템 권한에 대한 설명이 중요하다.

처음부터 여러 권한을 한꺼번에 요구하지 않는다.

기능을 설정하는 과정에서 필요한 이유를 먼저 설명한다.

예:

```text id="8rsqj3"
앱 실행을 확인하려면
접근 권한이 필요해요.

어떤 내용을 입력했는지는 확인하지 않아요.
앱이 실행되었는지만 확인합니다.

[계속]
```

사용자에게 **무엇을 감지하고 무엇을 감지하지 않는지** 명확하게 알려준다.

# 22. 기술 구조

1차 플랫폼은 Android로 한다.

핵심적으로 필요한 것은 다음 세 가지다.

### ① 현재 실행 앱 감지

사용자가 어떤 앱을 실행했는지 확인한다.

### ② 규칙 엔진

```text id="md1f5o"
패키지
+
현재 날짜
+
요일
+
현재 시간
+
오늘 실행 기록
        ↓
규칙 판단
```

### ③ 사용자 개입

조건에 따라:

- 실행 전 Confirm
- 실행 확인 알림

중 하나를 실행한다.

Android의 접근성 관련 기능, 사용 기록 접근 등의 시스템 기능을 검토하여 구현 방식을 결정한다.

Google Play 출시를 전제로 한다면 접근성 API 사용 목적과 Play 정책을 **개발 초기 단계에서 먼저 검증해야 한다.**

# 27. 향후 확장: 랜덤 메시지

예:

### 업무시간

```text id="5f4cbe"
돈 벌어야지.

지금 진짜 YouTube 볼 시간이야?

5분만 본다고?

오늘 할 일은 끝냈어?
```

실행할 때마다 하나를 무작위로 표시한다.

반복 사용 시 메시지가 익숙해지는 문제를 줄일 수 있다.

# 28. 향후 확장: 행동 연결

두 종류의 규칙을 연결할 수도 있다.

예:

> 오늘 운동 앱을 아직 실행하지 않았다.

이 상태에서 게임을 실행하면:

```text id="r5q4q8"
┌──────────────────────────┐
│                          │
│      운동은 하고 게임해?  │
│                          │
│   운동 열기      게임 열기 │
│                          │
└──────────────────────────┘
```

운동 앱을 오늘 한 번 실행했다면 게임을 실행할 때 이 Confirm은 나타나지 않는다.

이 기능은 상당히 강력하지만 MVP 이후 기능으로 둔다.

# 29. 제품이 하지 않는 것

이 부분을 명확하게 유지한다.

이 앱은 사용자의 스마트폰을 통제하는 앱이 아니다.

### 하지 않는다

- 앱 강제 차단
- 휴대폰 강제 잠금
- 목표 실패 처벌
- 사용자가 앱을 못 열게 만들기

### 한다

- 행동 직전 한 번 질문
- 잊은 행동 상기
- 사용자가 직접 만든 메시지 표시
- 최종 결정권은 사용자에게 제공

# 30. 제품의 핵심 구조

결국 제품 전체는 매우 간단한 두 문장으로 설명할 수 있다.

## 하지 않으려고 했는데 열었다면

> **한 번 물어본다.**

## 하려고 했는데 아직 안 열었다면

> **한 번 알려준다.**

이 두 가지가 제품의 중심이다.
